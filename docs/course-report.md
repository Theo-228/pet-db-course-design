# PetOS 数据库课程设计报告草稿

> 根据仓库中的原始讨论和实际实现整理。老师的 PPT 原件及最终评分细则尚未入库，提交前应对照原件补全格式与特定要求。

## 1. 需求分析

目标是构建家庭与猫咖共用的宠物健康及智能设备工作台。系统支持多宠物、多设备、多区域；可录入健康记录和设备测量，通过确定性规则产生提醒或模拟设备动作。课程版明确排除会员、订单、收费、排班等商业模块。所有 AI 能力只定义接口，不伪造诊断或问答结果。

核心场景包括：宠物档案及健康观察；设备注册与动态绑定；带时间戳的设备/人工测量；共享设备身份不确定时保留未知；用户确认后追加归属修订；基于测量值的阈值规则与可审计执行；跨工作空间数据隔离。

## 2. 概念与逻辑设计

E-R 图见 [数据库设计](database-design.md)。核心实体有 workspace、space、pet、device、device_pet_binding、metric_type、measurement、measurement_attribution、health_record、automation_rule、automation_dispatch、automation_execution、device_command、alert_event、user_account、workspace_membership。以 workspace 主键作为租户边界，跨实体关联尽量使用 `(workspace_id, id)` 组合外键，防止误连另一工作空间的数据。

宠物和设备是多对多的时态联系，绑定区间采用左闭右开 `[bound_at, unbound_at)`。排他约束保护时间段不重叠，专属设备同一时刻仅服务一只宠物。测量原始值与身份归属拆为两表，避免共享设备的总量被错误归给任意一只宠物。归属记录只追加，新旧判断均可追溯。

指标目录包含单位、对象范围、上下界和观测区间要求；设备能力表限制不同设备类型可上报的指标。原始测量和归属历史不可更新/删除。自动化执行保存规则快照、唯一键和动作关联，便于审计与重复事件防护。

## 3. 物理设计与 SQL

版本迁移在 `database/migrations/V1…V7`：核心关系、指标目录、统计视图、完整性守卫、测量语义、账号权限、自动化待处理队列。主要索引覆盖工作空间+时间范围、设备+事件去重、有效绑定区间、待处理告警和自动化待处理扫描。数据库使用 `btree_gist` 为区间排他约束提供支持。

统计视图：`v_measurement_current` 取得最新归属；`v_pet_latest_weight` 取得每只宠物最近体重；`v_pet_daily_totals` 汇总本地日期活动、进食和饮水；`v_device_last_measurement` 查询设备最近测量。复杂查询样例见 `database/queries/demo_queries.sql`，包括多表连接、CTE、窗口函数和聚合。应用在健康统计 API 中实际使用视图，而非只将 SQL 放在文档中。

## 4. 事务与一致性

注册账号、工作空间及 OWNER 关系在一个事务中创建。人工测量与宠物归属在同一事务中写入，并由延期约束触发器核实。设备测量写入时，数据库同时产生持久化自动化待处理行；提交后服务尝试规则执行，进程退出后定时扫描重试。单条规则执行与告警/指令动作在同一事务中提交，`(rule_id, measurement_id)` 防止重复执行。若规则执行失败，不回滚已提交的原始测量。

数据库触发器再次检查规则状态、阈值、来源过滤、宠物归属和冷却；成功执行必须有对应动作记录。设备指令是模拟状态，不是硬件确认。当前系统只模拟可控动作，不产生真实医学判断。

## 5. 前后端实现

后端以 Spring Boot、MyBatis、Bean Validation、Spring Security 和 Flyway 实现。前端 Vue 3 + Element Plus 提供登录、总览、宠物、设备、测量、自动化和 AI 占位页面。授权在服务层按 workspace 校验；API 统一用 JSON 传输。启动及接口说明见 [根目录 README](../README.md) 与 [应用设计](application-design.md)。

## 6. 测试与验收证据

- PostgreSQL 17 上执行 `database/tests/schema_test.sql`：对约束、归属、区间、规则动作及统计视图做事务内测试，末尾回滚。
- 后端以 Maven 执行 `test package`；前端以 `npm run build` 进行生产构建。
- `backend/scripts/smoke.ps1` 对运行中的真实 API 验证注册、空间授权、设备绑定、测量归属、告警、模拟设备命令、共享设备未知身份与修订、重复事件拒绝、健康报告、跨空间拒绝。
- 本地浏览器验证登录、总览、宠物档案、健康记录及统计展示，并修正窄屏侧栏溢出。
- 在后端停止时直接写入合法测量与归属，确认待处理行为 `PENDING`；重新启动后自动扫描将其标记为 `COMPLETED` 并生成两条规则执行记录，验证进程中断恢复路径。

测试脚本会创建开发测试数据，应在独立库中运行。当前没有真实硬件联调、AI 集成测试或课程评分细则对照结果；不能将这些列为已通过。

## 7. 局限与扩展

当前规则为单指标比较，不处理多信号决策；共享设备的 `IDENTIFIED` 归属依赖用户/外部识别结果，系统不会凭绑定猜测身份；多时区、海量时序分区、真实设备协议、通知渠道、模型与知识库均留待后续阶段。若需要投入猫咖试点，应补齐设备鉴权、真实回执、故障监控、备份恢复、访问审计和隐私评估。以上属于课程版外的工程工作，不应在答辩中宣称已实现。
