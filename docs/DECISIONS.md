# 设计决策记录

本记录区分用户明确要求、当前讨论基线与后续待确认事项。详细背景见 [原始讨论](chat-history/2026-10-14-pet-platform-discussion.md)。

| 编号 | 状态 | 事项 |
|---|---|---|
| D-001 | 已确认 | 本阶段作为**前后端分离的数据库课程设计** |
| D-002 | 已确认 | 家庭与猫咖使用**统一系统**，不按使用人群拆分功能模块，尽量减少日常人工操作 |
| D-003 | 已确认 | **暂不做商业化功能**，如会员、订单、收费、门店经营管理 |
| D-004 | 已确认 | **所有 AI 只留接口**，不接入模型、知识库或实现真实 AI 分析/智能问答 |
| D-005 | 已确认 | Git + GitHub 用于项目版本管理和同步 |
| D-006 | 当前讨论基线 | **四大模块**：宠物管理、智能设备管理、智能自动化中心、AI 智能助手 |
| D-007 | 当前讨论基线 | **AI 健康分析归入宠物管理**；智能任务/预警升级为智能自动化中心 |
| D-008 | 技术选型建议 | Java 21、Spring Boot 3.5.x、MyBatis Starter 3.0.x、PostgreSQL 17、Vue 3、Vite、Element Plus、Axios、Maven |
| D-009 | 当前讨论基线 | 无实际硬件时用**模拟设备**和真实数据库操作完成流程；普通规则、统计、阈值预警正常实现 |
| D-010 | 已完成课程版 | 数据库实体、关系、接口、Vue 页面与可演示的设备测量—规则—动作闭环已实现；真实硬件/AI 仍不在范围内 |
| D-011 | 待确认 | 教师 PPT 原件、完整评分细则、用户本地环境 |
| D-012 | 数据库实现选择 | 以 `workspace` 统一家庭与猫咖的数据边界，按相同实体和约束管理多宠物、多设备、多空间；原因是避免按场景复制业务表。影响：所有业务表与查询均须限定 workspace。 |
| D-013 | 数据库实现选择 | 原始测量不可变，归属判断使用可追加的修订记录；共享设备无法识别宠物时保留未知。原因是避免凭设备关联误认宠物并保留修正历史。影响：`measurement`、`measurement_attribution` 及统计视图。 |
| D-014 | 数据库实现选择 | 自动化仅使用确定性阈值规则；执行时验证条件并保存规则快照，动作和执行通过事务关联。原因是确保规则运行可审计、可幂等，且不依赖 AI。影响：`automation_rule`、`automation_execution`、`alert_event`、`device_command`。 |
| D-015 | 已实现 | 使用 Session + CSRF 与 workspace membership 做访问控制；原因是课程版统一 Web 工作台不需要额外的外部认证服务。影响：`user_account`、`workspace_membership` 与全部业务 API。 |
| D-016 | 已实现 | 测量插入时持久化 `automation_dispatch`，提交后处理、定时重试；原因是避免进程退出导致测量已保存而规则完全丢失。影响：V7 迁移和自动化服务。 |

注意：原始聊天前半段围绕未来创新创业和猫咖商业化做了大量**头脑风暴**，被后半段明确收窄。不要把历史的建议性功能当成必须交付的任务。

每次新设计决策建议记录日期、决策内容、选项与理由、影响的数据库表/API/页面。
