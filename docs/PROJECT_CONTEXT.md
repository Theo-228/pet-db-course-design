更新：2026-10-14。**优先阅读原始讨论：[`docs/chat-history/2026-10-14-pet-platform-discussion.md`](chat-history/2026-10-14-pet-platform-discussion.md)**。本文件是按聊天后半段的最新决定整理的摘要；聊天前半段有大量已被后续调整的商业化设想，不能误当现阶段开发需求。数据库初版及其运行方法见 [`database/README.md`](../database/README.md)。

## 当前定位

- **数据库课程设计**：做一个前后端分离、可运行的完整数据库应用。数据库关系、约束、事务、查询、索引、历史记录及业务流程是重点。
- **统一宠物智能管理平台**：家庭与猫咖共用同一系统，支持多宠物、多设备、多空间；不为不同人群分别开发两套业务系统，尽量减少对人工日常操作的依赖。
- **不做商业运营**：当前不开发会员、订单、收费、门店员工排班等商业化/ERP 模块。历史讨论中的商业产品规划仅作为最初构想。
- **全部 AI 仅留接口**：包括健康分析、行为识别、全局 AI 问答、AI 数据库查询、AI 决策；不开发模型、知识库、真实推理。普通 SQL 统计、设备模拟、确定性规则和阈值预警应正常工作。

## 当前讨论形成的四大核心模块

1. **宠物管理**：宠物数字档案、行为/饮食/体重/健康数据、健康报告；AI 健康分析在本模块下保留接口。
2. **智能设备管理**：项圈、电子秤、喂食器、饮水机等设备的注册、绑定、状态、模拟/真实数据记录及控制。
3. **智能自动化中心**：可配置规则、设备联动、普通阈值预警、执行结果与事件记录；AI 决策仅留接口。
4. **AI 智能助手**：全局专业问答、受控业务数据库问答等功能的 API 定义与前端占位，不实现真实 AI。

四大模块是目前开发基线。实际功能拆分、数据库实体及 API 需要在需求分析阶段进一步确认。

## 已推荐的开发技术路线

| 层次 | 当前建议 |
|---|---|
| 数据库 | PostgreSQL 17 |
| 后端 | Java 21、Spring Boot 3.5.x、MyBatis Spring Boot Starter 3.0.x、Maven |
| 前端 | Vue 3、Vite、Element Plus、Vue Router、Axios |
| API | RESTful API，Controller / Service / Mapper 分层 |
| 版本控制 | Git + GitHub，同步代码、SQL 和文档 |

上述为原始讨论后半段的**推荐组合**，并非老师逐项强制的版本；创建项目时须核对依赖兼容性与用户本地环境。

## 数据库课程设计重点

先完成需求与业务流程，再设计 E-R 图、关系模式和约束，最后进行代码实现。优先考虑：宠物与设备动态绑定、共享设备的身份归属不确定性、时序测量记录、自动化规则与事件执行日志、多表查询/聚合/CTE/窗口函数、事务一致性、视图及索引。没有真实硬件也可以用模拟数据完成端到端验证。
